Difficulties Faced and How We Overcame Them:

One difficulty we faced was understanding how sentence embeddings work and how they are different from simple keyword matching. At first, it was not immediately obvious how a user question could be converted into a numerical vector and compared to stored questions. We overcame this by researching the purpose of embeddings and then using the SentenceTransformer library to generate embeddings for all knowledge-base questions. Once the questions and user input were represented as vectors, we used cosine similarity to retrieve the most relevant stored question.
Another difficulty was making the semantic search reliable for slightly different or misspelled user inputs. For example, a user might type a question that does not exactly match any question in the CSV file. We overcame this by comparing the user query embedding against every stored question embedding and selecting the question with the highest similarity score. This allowed the assistant to still return a useful answer even when the wording was not identical.
We also had difficulty choosing and handling the sentiment analysis output. Different models may return labels in different formats, such as NEGATIVE, NEUTRAL, POSITIVE, or model-specific labels like LABEL_0, LABEL_1, and LABEL_2. We handled this by normalizing the sentiment labels inside the program so that the output would always be displayed clearly to the user. We also used the confidence score to avoid escalating every negative message and only recommend a human advisor when the negative sentiment was strong enough.
Another issue was making the program easier to debug and explain during the demo. If the chatbot only returned an answer, it would be harder to show how the semantic search was working. To solve this, we displayed the matched knowledge-base question and semantic similarity score along with the final answer. This makes the retrieval process more transparent and helps show that the program is selecting the closest matching question from the knowledge base.
We also had to manage environment setup and dependencies. Since the project uses several AI and machine learning libraries, including pandas, numpy, scikit-learn, sentence-transformers, transformers, and torch, we created a requirements.txt file to make installation easier and more consistent. This helped reduce setup problems and made the project easier to run on another machine.

What We Learned:

Through this project, we learned how to combine several AI and Python programming concepts into one working application. We learned how a CSV file can be used as a small knowledge base, how pandas can load and validate structured data, and how sentence embeddings can represent the meaning of text in a way that allows semantic comparison. We also learned how cosine similarity can be used to find the closest stored question to a user’s input.
We learned how sentiment analysis can be integrated into a chatbot to detect whether a user is positive, neutral, or negative. This helped us understand how AI systems can do more than simply answer questions; they can also react differently depending on the user’s emotional tone. The escalation logic showed how a simple rule can be added on top of a model’s output to make the assistant more useful in real support situations.
Overall, this project showed us that a useful AI-powered support assistant can be built with relatively little code by using existing Python libraries and models. It also helped us practice basic software engineering skills such as modular functions, file handling, error handling, testing, documentation, and organizing a project for submission.
